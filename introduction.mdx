N2AB Client is a presentational overlay client for [PolyTrack](https://polytrack.skyhost.fun), the browser-based racing game. It layers a toggleable panel, live telemetry readouts, and visual tools directly on top of the game without touching physics, the leaderboard, or any netcode. Everything it does is cosmetic and informational — speed graphs, frame-rate counters, split timers, input displays — rendered as fixed overlays that disappear as soon as a module is switched off.

<Note>
  N2AB Client is purely presentational. It does not modify car physics, race
  outcomes, leaderboard submissions, or any networked game state.
</Note>

## How it works

The client ships as a pre-built, obfuscated JavaScript bundle (`n2ab_client.bundle.js`) that is loaded by `index.html` alongside the main game bundle. Rather than editing minified code by hand, a repeatable build tool (`tools/build-n2ab-client.js`) applies three transforms each time it runs:

1. **Rebrand** — every upstream brand token (`PolyTraqqq`, `polyfly`, `ptq`, CSS custom-property prefixes, storage keys, etc.) is rewritten to the `N2AB` / `n2ab` namespace. The live update server and logo host (`polytraqqq.com`) are deliberately left intact so the auto-updater continues to work.
2. **UI polish** — `tools/ui-polish.css` is appended to the panel's shadow-DOM stylesheet.
3. **Module injection** — the code in `tools/modules.js` is wrapped in an IIFE and spliced into the bundle immediately after the built-in modules register, giving the extra modules access to the same `__api` feature registry.

The build is idempotent: running it any number of times produces a byte-identical output file.

## The panel and feature categories

All modules appear in a floating side panel that opens while the game is running. Each module belongs to one of four categories, which the panel uses to group entries:

| Category   | Purpose                                              |
|------------|------------------------------------------------------|
| `Movement` | Inputs, speed readouts, and handling feedback        |
| `HUD`      | In-race informational overlays                       |
| `Network`  | Connection and latency tools                         |
| `Render`   | Frame-rate, visual effects, and screen presentation  |

## Built-in modules

Seven modules ship with N2AB Client out of the box, all defined in `tools/modules.js`:

| Module         | Category | Description                                                        |
|----------------|----------|--------------------------------------------------------------------|
| `perfOverlay`  | Render   | FPS, frame time, and 1% lows in a compact corner readout           |
| `speedGraph`   | HUD      | Rolling speed trace so you can see where you bleed momentum        |
| `splits`       | HUD      | Logs checkpoint times and the delta against your best run          |
| `inputDisplay` | HUD      | Live WASD / arrow key overlay for recording and review             |
| `cleanScreen`  | Render   | Hides the game HUD for screenshots and video                       |
| `sessionStats` | HUD      | Top speed, average speed, and distance for the current session     |
| `theme`        | Render   | Recolours the client panel and overlays with an accent hue control |

## Settings persistence

Every module's active state and all per-setting values are serialised to the browser's `localStorage` under the key `N2AB_SETTINGS`. Settings round-trip automatically — the panel reads this key on load and writes it whenever any value changes. Individual settings can opt out of persistence by setting `transient: true` in their definition, which keeps the value for the current session only and never touches storage.
